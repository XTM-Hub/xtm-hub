# Menu → `@filigran/design-system`

## Intent

Every legacy `DropdownMenu*` part moves to the design system `Menu` compound, which wraps the same Radix primitive.
Who opens each menu, what each row does, which rows show, the accessible names of triggers and rows, and whether a
pick closes the menu stay the same for users. The panel, rows, label, separator and sub-menus take the design system
look.

## Props mapping

Rules shared by every row:

- **Parts**: `DropdownMenu` → `Menu`, `DropdownMenuTrigger` → `MenuTrigger`, `DropdownMenuContent` → `MenuContent`,
  `DropdownMenuItem` → `MenuItem`, `DropdownMenuLabel` → `MenuLabel` (inside a `MenuGroup`), `DropdownMenuSeparator`
  → `MenuSeparator`, `DropdownMenuSub`/`SubTrigger`/`SubContent` → `MenuSub`/`MenuSubTrigger`/`MenuSubContent`.
  `DropdownMenuPortal` around a sub-panel goes: `MenuSubContent` portals by default.
- **Radix props stay**: `open`, `onOpenChange`, `asChild`, `align`, `disabled`, `onClick`, `onSelect`. `onClick` stays
  where the legacy used it: Radix fires it on pointer and keyboard selection alike, and the unit tests stub it.
- **Restyling goes**: every `className` on `MenuContent`, `MenuItem` and `MenuSeparator` (`w-[160px] z-[1500]`,
  `w-80 p-0`, `p-0`, `bg-foreground/20`, `capitalize`). A leading icon in a row's children moves to `startIcon`,
  keeping its `@filigran/icon` glyph at `size-4` without margin or colour class.
- **No radio or checkbox item** in the design system (contract, "Out of scope"): a radio or checkbox row becomes
  `<MenuItem selected={isCurrent} onSelect={pick}>`, the `check` indicator `TabsMenuTrigger` uses for its current
  entry. A pick still closes the menu, as the legacy items did.

## Accessibility and i18n

- Radix still gives the trigger `aria-haspopup="menu"` and `aria-expanded`, the panel `role="menu"`, rows
  `role="menuitem"`. `MenuGroup` names `ServiceListIntegrationDropdown`'s rows by its label.
- Radio and checkbox rows (`menuitemradio`, `menuitemcheckbox` with `aria-checked`) become `menuitem` with

- Tab inside an open panel stays swallowed by Radix, as in the legacy: `ConnectProductButton` in the connected
  products panel stays out of keyboard reach.
- No translation key added or removed.

## Decisions

- **`Menu`, not `Select`, for rows per page and column visibility**: both live in a sub-menu of a command menu
  (reset table, columns, page size); splitting them into `Select` fields would change the toolbar, not swap a part.
- **`selected` for radio and checkbox rows**: the design system ships neither item; `selected` keeps a visible
  check on the current choice and keeps one pick per opening, as the legacy items closed the menu on select.
- **`IconActions` keeps its `div` trigger**: moving `MenuTrigger` onto the `Button` would change what the unit tests
  and e2e click; it is listed under Deferred findings.
- **`z-[1500]` goes**: no `IconActions` renders inside a sheet or dialog, and the design system panel stacks on
  `--fds-z-overlay` (50) in a portal mounted after the page.
- **`ConnectedProductItem` loses its own padding** so that the 300px design system panel holds the icon, title, chip
  and the two link buttons; it renders only in this panel.
- **`capitalize` moves to a `span`** in the column rows: it formats the column identifier, not the row.
- **The legacy numeric spacing steps go now** (epic review), an exception to "leave the legacy theme alone": the legacy
  `theme.css` declared `--spacing-50` to `--spacing-1800` on a 0.125rem scale, so Tailwind resolved the design
  system's `min-w-50` to 2px instead of 200px, and its `w-50` (`SearchField`) and `w-100` / `max-w-100` (`Snackbar`)
  the same way. No class of the app used those steps; the navigation popover's `w-50` now gives the 200px it meant.
  Menus take the design system's 200 to 300px panel: `IconActions` panels grow from 160 to 200px, and the
  `Snackbar` viewport loses its width patch. One rule: the design system's own sizes win.

## Deferred findings

- Design system: no `MenuCheckboxItem` / `MenuRadioItem`; `aria-current` on several column rows is not a checked
  state. To raise upstream.
- `IconActions`: `MenuTrigger` should sit on an `IconButton` with `aria-label` (contract RULE-01), not a `div`
  around a `Button`; `label`, `IconActionsButton` and `IconActionContext` are unused.
- `OrganizationList`: the "Subscribed services" row should be `MenuItem asChild` > `Link` (contract: a navigating row
  is a real anchor).
- `ConnectedProductsDropdown`: the panel holds non-menu content (link buttons inside rows, a footer `Button`), which a
  popover would fit better; the design system ships none.
- `ConnectedProductsDropdown`: `MenuContent` scrolls on its own, so the kept `max-h-[70vh]` list nests a second scroll
  area in a short window.
- `ConnectedProductItem`: its root keeps `hover:cursor-default` inside a `cursor-pointer` row, and its `div`s now sit
  in `MenuItem`'s label `span`.
- Column menu icons stay `@filigran/icon` glyphs rather than the design system `Icon` the contract asks for.
- Legacy `DataTable`: the column visibility, rows per page and column header menus have no unit test; item 3705
  replaces them.
- `ConnectedProductsDropdown` and `IconActionsLink` (`MenuItem asChild` > `Link`) have no unit test; the
  `IconActions` tests mock the module.
