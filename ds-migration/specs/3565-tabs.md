# Tabs → `@filigran/design-system`

## Intent

The four call sites still on the legacy `Tabs*` parts move to the design system `Tabs` compound, which wraps the same
Radix primitive (`RoleList` already uses it). Which tab opens first, which tabs show or are disabled, what each panel
holds and the tab accessible names stay the same. The bar takes the design system look: full-width bottom rule, 44px
triggers, brand underline, semibold active label.

## Props mapping

Rules shared by every row:

- **Parts**: same names, imported from `@filigran/design-system` instead of `@filigran/ui`. `Tabs` keeps the default
  `panels="content"`: every call site renders one `TabsContent` per trigger.
- **Radix props stay**: `defaultValue`, `value`, `disabled`, `key`. `activationMode` is not passed: the design system
  default `manual` applies (contract RULE-04).
- **Panel gap**: the legacy `TabsContent` carried `mt-2`; the design system one has none. Each `TabsContent` whose
  first child has no top margin of its own gets `className="pt-l"`, the gap `RoleList` already uses.

## Decisions

- **`TrialGuidePage` loses its bar and trigger restyling**: it hand-built the underline bar the design system
  `TabsList` and `TabsTrigger` now draw (`border-b`, `border-b-2` indicator, `-mb-px`); keeping it would fight them.
- **XTM One keeps its accent**: the gradient icon and `filigran-ia-main` active label are product branding the page
  ships (the gradient `svg` exists only for it), not the legacy look. The label colour moves to the trigger's
  `className` so the label stays a plain string and keeps the design system's bold-width reservation.
- **Icon in the `icon` slot**, not in the children: the contract's leading-icon slot (RULE-06), 16px as before.
- **`pt-l` for the panel gap**: the only design system `Tabs` in the app (`RoleList`) answers it this way.
- **Manual activation kept**: `TrialsList` panels each run a query; the contract keeps `manual` when switching has a
  side effect.
- **The XTM One accent reads the design system token** (epic review): `text-filigran-ia-primary` from the imported
  `tokens/theme.css`, same values as the legacy `--color-filigran-ia-main`, so it survives the legacy theme's removal.
- **`ContentEditDialog` has no screen**: it opens only in content edit mode, from a hover on an editable text; its
  structure is the plain `TrialsList` one.

## To validate

- Panels sit 16px under the bar (`pt-l`, as `RoleList`) instead of the legacy 8px. Alternative: `pt-s` (8px).
- Keyboard: arrow keys move focus without switching the panel, where the legacy switched on focus. Alternative:
  `activationMode="automatic"` on `ContentEditDialog` and `UserListPage`, whose switch is instant.
- `TrialGuidePage`'s XTM One tab keeps the `filigran-ia-main` label and gradient icon while active, over the design
  system brand colour; its underline stays brand. Alternative: drop the accent and use the stock active state.
- Every bar now spans its container with a bottom rule (the design system `TabsList`), including the four-locale bar
  in `ContentEditDialog`. Alternative: none without restyling.

## Deferred findings

- `UserListPage`: the pending users tab is disabled at zero and carries its count in the label; the contract prefers
  hiding an unavailable tab (RULE-09) and showing a count with `badge` + a translated `badgeLabel` (RULE-07). Moving
  the count changes the accessible name `user.spec.ts` uses.
- `UserListPage.test.tsx` stubs the tab parts instead of rendering them, so the disabled state is checked on a stub.
- The gradient `svg` of `TrialGuidePage` and `PlatformIdentifierMapping` still read `--color-filigran-ia-main`, defined
  only in the legacy `theme.css`; the design system ships `--color-filigran-ia-primary` with the same values. Cleanup
  3708 must remap them or the accent silently disappears.
- The design system `TabsList` scroll buttons carry hard-coded English `aria-label`s ("Scroll tabs left/right") with no
  prop to translate them; an upstream gap, visible only when a bar overflows.
- The design system `TabsList` runs a dependency-less effect that reads layout on every render; harmless at these call
  sites, worth an upstream note.
- Test gaps that already existed: `TrialsList` has no unit test (Quotas tab only for bundles), `ContentEditDialog.test.tsx`
  never switches locale, `TrialGuidePage.test.tsx` matches tab names by regex, and no test covers manual activation.
- `UserListPage` reads `selectedTab` from the URL into an uncontrolled `defaultValue`, so a same-route link with
  `?action=approve` does not switch tabs (unchanged by this item).
