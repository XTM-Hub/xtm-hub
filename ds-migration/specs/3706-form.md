# Form → `@/components/ui/form`, rebuilt on `react-hook-form`, Radix `Slot`, the `Label` candidate and `Text`

## Intent

The design system ships no form layer: its fields draw their own label, required marker and error row, and stay
decoupled from any form library. The legacy `Form.tsx` (the shadcn `react-hook-form` binding: `Form`, `FormField`,
`FormItem`, `FormLabel`, `FormControl`, `FormMessage`, `FormDescription`, `useFormField`) is used by about 50 files and the
whole legacy `AutoForm`. It is rebuilt as a candidate in `src/components/ui/form/` on the same engine, so the labels,
required markers and error messages it draws match the ones the design system fields draw next to them. What users
get stays: the same fields, ids, label association, `aria-invalid` and error messages. Changed on purpose (team
feedback on #3715, comment on #3706): since 3691, `FormLabel` already draws the design system label size and colour
(the before screens show Description, Logo and Images matching their neighbours); what is left is the Description
star, still a 14px `text-destructive` span, which takes the design system required marker, and `FormMessage`, which
takes the design system error row.

## The component

`src/components/ui/form/`, the package layout:

- `Form.tsx` (`'use client'`):
  - `Form` = `react-hook-form`'s `FormProvider`; `FormField` = `Controller` inside the field-name context, same
    generics (`TFieldValues`, `TName`) as the legacy.
  - `FormItem`: a `div`, `flex flex-col gap-2` (the design system field gap, the legacy `gap-s` value), the caller's
    `className` merged last with the app's `cn` (`@/lib/utils`), ref forwarded, `useId` in the item context.
  - `useFormField()`: `{ id, name, formItemId, formMessageId, ...getFieldState(name, formState) }`. It tolerates being
    called outside a `FormField` or `FormItem`, as the legacy did (two call sites rely on it, see Props mapping); the
    legacy dead `if (!fieldContext)` throw goes.
  - `FormLabel`: `Label` from `@/components/ui/label` with `htmlFor={formItemId}` and `error={Boolean(error)}`; props
    `Omit<LabelProps, 'error'>`, so it now takes `required`; ref to `HTMLLabelElement`.
  - `FormControl`: `Slot` from `@radix-ui/react-slot` (a design system dependency) with `id={formItemId}`,
    `aria-invalid={Boolean(error)}` and `aria-describedby={formMessageId}` only when there is an error (the legacy
    always pointed at a description id nothing rendered).
  - `FormMessage`: `Text as="p" variant="content-caption"` with `text-input-error` and `id={formMessageId}`, the
    caller's `className` joined, not `cn`-merged (the `Label` rule). Body: the field error's `message`, else
    `children`; renders nothing when empty.
  - Dropped, no caller: `FormDescription` and its id; the hard-coded English `'Invalid format'` fallback and the
    `String(undefined)` body of an error without message (the zod resolver always gives one).
- `Label` (`src/components/ui/label/`), the shared answer for the required marker (3691 Deferred findings):
  `required?: boolean` (default `false`) appends, inside the label after `children`, `<Text as="span"
  variant="content-base" aria-hidden="true">*</Text>` with `ms-1` and `text-input-required`, `text-input-error` when
  `error` is set: the star the design system `Input` draws (`text-3`, regular, `aria-hidden`). `Label.meta.ts` gains
  the `required` prop, the `required` variant, an example and the `--text-input-required` contrast pair;
  `Label.test.tsx` covers the star (rendered, `aria-hidden`, colour, error colour, absent by default).
- `Form.meta.ts`: `FormMeta`, typed `ComponentMeta` (type import only): description (the `react-hook-form` binding
  for controls that do not draw their own label and error), `status: 'beta'`, `category: 'inputs'`, `version:
  '0.1.0'`, `radixPrimitive: '@radix-ui/react-slot'`, variants `default`, `error`, `required`, examples (a
  `FormField` rendering `FormItem` / `FormLabel` / `FormControl` / `FormMessage`; a design system `Input` inside a
  bare `FormField`), `props` per part, `accessibility` with `wcagStatus: 'pending'`, the contrast pair
  `--text-input-error` on `--bg-elevation-default` at 4.5 and notes (label `htmlFor` on the control id,
  `aria-invalid`, `aria-describedby` to the message, the star `aria-hidden`).
- `Form.test.tsx` (real `react-hook-form`, `testRender`): the label names the control through `FormControl`;
  `FormItem` merges `className`; after a failed submit `aria-invalid` is true, `aria-describedby` points at the
  message, the message shows the zod text in `text-input-error` and the label takes `text-input-error`; no message
  and no `aria-describedby` while valid; `FormMessage` shows `children` without an error; `required` draws the
  `aria-hidden` star; `FormLabel` outside a `FormField` renders without throwing. This covers the 3691 Deferred
  finding on the untested error colour.
- `index.ts`: exports the seven parts and the `FormItemProps`, `FormLabelProps` types, never the meta.

## Decisions

- **Same engine**: `react-hook-form` and Radix `Slot` stay (the design system depends on `@radix-ui/react-slot`
  itself); the candidate swaps the legacy label, spacing and message classes for the `Label` candidate, `Text` and
  the `input` tokens.
- **`FormMessage` as the design system helper row**: `content-caption` (`text-1`, 10px, regular) in
  `text-input-error`, the row `Input` draws under itself, so a `FormMessage` reads like the field errors beside it.
- **The star lives on `Label`**, not on `FormLabel`: `AutoFormLabel` (3707) and any standalone label can then draw it
  the same way. Inside the `label` element, after the text, so callers that make the label a flex row
  (`EpicFieldLabel`, the Images label) keep their layout.
- **Caller classes that recreate the legacy look go** (`text-destructive`, `text-sm` on `FormMessage`): they would
  override the design system colour and size. Layout classes (`mt-2`, `md:flex-1`) stay.
- **Unused parts dropped**: `FormDescription` has no caller, as the Carousel and DataTable candidates dropped theirs.
- **`gap-2`** on `FormItem`: a design system spacing step equal to the legacy `gap-s` (0.5rem).

## Deferred findings

- `FormControl` sets no `aria-required` when the label draws the star; the design system fields do. Where the control
  is a `div` (`JsonFileField`, `OpenaevScenarioForm`'s file field) or `MarkdownInput`, the `htmlFor` / `id` pair names
  no form control at all.
- The two `FormLabel`s outside a `FormField` (`ServiceSlugOrgaForm`, `UserServiceForm`, "Select capabilities") point
  `htmlFor` at `undefined-form-item`: they title a checkbox group and would be a `fieldset` / `legend`.
- The Images label wraps an `IconButton` (interactive content inside a `label`), and the images input is hidden, so
  the label names nothing a user can reach.
- `FormItem hidden` is used by three `AutoForm` configs to hide a field; an `AutoForm` option would say it.
- `FormControl` points `aria-describedby` at the message id whenever the field has an error, even where no
  `FormMessage` renders it (`EpicForm` edition type, `AutoForm` `Checkbox` and `Switch`) or where the error has no
  top-level `message` (an array or object field): the id then names nothing, and such an error shows no text.
- `FormMessage` draws its `children` in `text-input-error` even without an error; the design system helper row
  switches to `text-input-helper` then. No caller passes children today.
- The `Label` star picks only between `text-input-required` and `text-input-error`; the design system fields use
  `text-input-disabled` on a disabled field (`DescriptionField` passes `disabled` to its control).
- `EpicFieldLabel` takes `required`, but its only caller never passes it; were it set, the star would follow the info
  tooltip button, after both the `gap-xs` row gap and its own `ms-1`.
- The field and item contexts default to `{}` cast to their types, so `useFormField` outside a `FormField` returns
  `name: undefined` and a shared `undefined-form-item` id typed as `string` (carried over from the legacy).
- `useFormField` reads the proxied `formState` of `useFormContext`, which subscribes the whole form to errors, dirty
  and touched state: a form using these parts re-renders on every edit (carried over from the legacy).
